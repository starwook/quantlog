# 내 매매 원칙

지금 이 봇이 어떤 원칙으로 움직이는지 정리한 문서입니다. 바꾸려면 저와 대화해서 정하고, 바뀐 내용은 [변경 이력](principles-log.md)에 남습니다.

## 지금 이렇게 하고 있다 (확정)

- **롱만 한다.** 공매도·인버스·레버리지는 안 한다.
- **결과를 보고 개선한다.** 익절·손절 % 같은 숫자는 고정이 아니라, 기록을 보면서 더 나은 값으로 바꿔간다.
- **청산은 기계적으로, AI 없이 한다.** 익절 +1% / 손절 -1% (아직 임시값). 가격이 그 선에 닿으면 스케줄러가 그냥 판다. 목표가는 평단 ±1%에 **가장 가까운 호가**로 잡는다 (호가 단위는 종목·가격대마다 달라 증권사 시세에서 받음. 예: 평단 272,000원 → 익절 274,500 / 손절 269,500).
- **감시 종목은 반도체로 좁힌다.**
  - 국내: 삼성전자(005930), KODEX 반도체(091160)
  - 미국: SOXL (AMEX)
- **시장별로 쓸 돈을 나눈다.** 국내 500만원 / 미국 500만원 상당. 이 한도를 넘겨서 새로 사지 않는다.
- **하루 손실 한도(킬스위치).** 그 시장에 배분한 돈의 -3%를 잃으면, 그날은 새로 사지 않는다. (국내 약 -15만원 / 미국 약 -$81)
- **물타기 안 한다.** 떨어진 종목을 더 사서 평단을 낮추는 행동은 하지 않는다.
- **5거래일 넘게 안 들고 있는다.** (타임스톱, 아직 임시값)

## 아직 정하는 중 (2026-09-29 밤에 열린 질문, 다음에 이어서 정함)

- **매수 판단에 AI가 꼭 필요한가?** 지금까지 나온 진입 아이디어(오늘 -5%/-10%면 매수 등)는 전부 숫자 기준이라, AI 없이 코드만으로도 할 수 있다는 얘기가 나왔다. → **결론 안 남.** 다음 대화에서 "규칙만으로 갈지" "AI를 어디에 쓸지" 다시 정한다.
- 구체적인 매수 규칙(몇 % 빠지면 사는지 등 정확한 숫자)
- 클라우드 서버 배포 (지금은 로컬에서만 테스트 중이라 컴퓨터 끄면 봇도 멈춘다)
- **진입 판단 데이터 형태 (2026-09-29):** 차트 이미지를 매번 캡처해서 보여주는 방식 대신, KIS API로 받은 OHLC(시가·고가·저가·종가)·거래량 숫자로 판단하는 쪽으로 방향을 잡음. 자동화·재현 가능성 때문. **국내 분봉 조회(`FHKST03010200`) 스펙 확인 완료, 구현 완료** — 당일 데이터만·1회 최대 30건이라 받는 족족 DB(`minute_candle`)에 쌓는 구조로 만듦.
- **분봉 기반 진입 규칙 (2026-09-29, 검증 전, 두 번째 버전):** 첫 시도는 모멘텀(5분 수익률)+거래량 급증 동시 충족이었는데, 사용자가 "거래량까지 볼 필요 있나, 횡보하다 저점 찍으면 거기서 사는 걸 원한다"고 해서 폐기. 지금은 **당일 저점(그날까지의 최저가) 대비 0.3% 이내로 붙었다가 직전 분봉보다 올랐으면(반등 시작) 매수** — 거래량 조건 없음. 분봉이 15개(약 15분) 안 쌓였으면 매수 안 함(장 시작 직후 오탐 방지). AI 판단 없이 순수 숫자 규칙, `strategy/EntryRule.kt`의 `SupportBounceEntryRule`, 설정은 `quantlog.strategy.entry.*`. **실제 EntryScheduler에 연결되어 정규장 중 자동 매수함**(모의투자). 임계값(0.3%, 15개)은 첫 가설값이라 로그가 쌓이면 검증해야 확정.
- **차트 화면에 표시하는 종목 (2026-09-29):** 삼성전자(005930)·SK하이닉스(000660)·SOXL(AMEX) 세 개, `com.quantlog.chart.WATCHED_SYMBOLS`. 단, **자동매수(EntryScheduler) 감시 종목은 그대로 삼성전자·KODEX반도체(091160)** — 화면 표시용 종목과 자동매매 대상 종목을 의도적으로 분리해뒀다(사용자가 화면 종목은 바꾸되 자동매매 대상은 그대로 두기로 함). SOXL은 해외라 분봉 조회가 안 돼 차트가 항상 비어 있다.
- **풋/콜 옵션을 진입 판단에 쓸지 (2026-09-29):** 검토 대상. (정정 2026-09-29: KIS에도 국내 옵션 API가 있다 — `국내옵션전광판_콜풋`(FHPIF05030100), 주식옵션 호가/체결 등. 삼성전자 같은 개별 주식옵션의 행사가별 미결제약정이 여기서 나오는지, 모의투자에서 되는지는 실제 호출로 확인 필요.) **옵션을 사고파는 게 아니라, 미결제약정이 몰린 가격대(맥스페인 등)를 신호로만 보고 그 가격대에 현물을 매수하는 방식** — 그래서 "롱만 한다" 원칙과 안 부딪힘(사용자 확인). 데이터 소스 후보 조사 완료(무료 웹 도구/유료 API/비공식 스크래핑, 공식 무료 API는 없음) — **일단 보류, 분봉 기반 진입 판단부터 먼저 진행하기로 함.**

## 봇의 판단 습관

- 근거 없으면 안 산다. 근거는 일지에 남긴다.
- 확신 없으면 쉰다. 쉰 이유도 일지에 남긴다.
- 없는 데이터(옵션, 국채금리 등)는 아는 척하지 않는다. 아직 연결 안 됐으면 "데이터 없음"이라고 적는다.

## 절대 안 바뀌는 것

리스크 가드(1회 주문 한도, 시장별 자본 배분, 하루 손실 한도, 비상 정지)는 다른 모든 원칙보다 우선한다. 봇 스스로도, 학습으로도 이걸 우회할 수 없다.

## 아직 채택 안 한 아이디어 (판단에 안 씀)

- 국채금리 급등한 날은 쉰다 — 금리 데이터 연결 필요, "급등"의 기준 필요
- 콜옵션이 특정 수준이면 매수 — 옵션 데이터 연결 필요
- 익절 +2%쯤, 손절은 더 과감히 — 기록 쌓이면 비교해서 결정

## 원칙을 바꾸는 방법

1. 저와 대화해서 정하거나, 봇이 스스로 배운 걸 제안하면(`proposals/`) 제가 검토해서 반영합니다.
2. 익절·손절 같은 숫자만, 정해진 범위 안에서 자동으로 조정될 수 있습니다.
3. 거래가 적을 때(50건 미만) 나온 결과로는 원칙을 안 뒤집습니다.
4. 바꿀 때마다 이유와 날짜를 [변경 이력](principles-log.md)에 남깁니다.
