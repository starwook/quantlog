# 내 매매 원칙

지금 이 봇이 어떤 원칙으로 움직이는지 정리한 문서입니다. 바꾸려면 저와 대화해서 정하고, 바뀐 내용은 [변경 이력](principles-log.md)에 남습니다.

## 한눈에 보기 (전략 겹침·빈틈 질문은 여기서 답한다 — 코드를 열지 않는다)

원칙을 바꿀 때마다 이 표도 같이 고친다. 상세는 아래 본문.

**매수 경로 (삼성전자, 마틴게일 ON)**

| 경로 | 조건 | 쓰이는 때 |
|---|---|---|
| 저점 신호 | 당일 저점 0.3% 이내 + 반등 | 보유 0주, 재진입 규칙 없을 때 첫 1주 |
| 마틴게일 추가매수 | 평단 -0.5%마다 보유 수량 2배로, 최대 5단계(새 종목 기본 10) | 보유 중 |
| 재진입 | 직전 매도가 -0.5%(익절 뒤) / -1%(손절 뒤) | 매도 직후. 이때 저점 신호는 안 봄 |

**매도 경로**

| 경로 | 조건 | 비고 |
|---|---|---|
| 익절 | 평단 +0.5% 전량 | 유일한 일반 매도. 종목별 DB 값 |
| 마틴게일 손절 | 최대 단계 매수 뒤 평단 -3% | 1~4단계엔 손절 없음 |
| 전역 손절 | 보류 | 안 나감 |
| 타임스톱 | 미정 | 코드 없음 |

**겹침·빈틈 메모:** 첫 사이클 이후엔 재진입이 저점 신호를 사실상 대체한다 / 1~4단계는 익절 말고 나갈 길이 없다.

## 지금 이렇게 하고 있다 (확정)

- **롱만 한다.** 공매도·인버스·레버리지는 안 한다.
- **결과를 보고 개선한다.** 익절·손절 % 같은 숫자는 고정이 아니라, 기록을 보면서 더 나은 값으로 바꿔간다.
- **청산은 기계적으로, AI 없이 한다.** 익절 **+0.5%** (2026-09-30 임시로 +1%에서 줄임 — 오늘은 수익률보다 최대한 많이 거래하는 게 목표. 이 값은 전역 설정이라 KODEX 반도체·SOXL에도 적용된다). **전역 손절은 보류 중이다** — 떨어져도 일반 손절 매도는 안 나간다(삼성전자의 5단계 손절은 아래). 가격이 익절 선에 닿으면 스케줄러가 그냥 판다. 목표가는 평단 +0.5%에 **가장 가까운 호가**로 잡는다 (호가 단위는 종목·가격대마다 달라 증권사 시세에서 받음. 예: 평단 272,000원 → 익절 273,500).
- **감시 종목은 반도체로 좁힌다.**
  - 국내: 삼성전자(005930), KODEX 반도체(091160)
  - 미국: SOXL (AMEX)
- **시장별로 쓸 돈을 나눈다.** 국내 **1000만원**(2026-09-30 상향, 원래 500만원) / 미국 500만원 상당. 이 한도를 넘겨서 새로 사지 않는다.
- **1회 주문 상한은 없다 (2026-09-30 폐지, 미국 포함).** 예전의 주문 1건당 금액·수량 상한은 지웠다. 한도는 위 시장별 배분과 아래 하루 손실 한도가 맡는다.
- **하루 손실 한도(킬스위치).** 그 시장에 배분한 돈의 -3%를 잃으면, 그날은 새로 사지 않는다. (국내 약 -30만원 / 미국 약 -$81). 마틴게일 5단계 손절로 실현손실이 생기므로 이제 실제로 작동한다.
- **오늘 살 종목·익절/손절 %·마틴게일 값은 DB에서 바꾼다 (2026-09-30).** 원칙이 자주 바뀌어서 코드를 안 고치려고 `symbol_strategy` 테이블(종목별)로 뺐다. 값을 UPDATE 하면 재시작 없이 반영된다(사용법은 README). 아래 숫자들은 **기본값**이고, 지금 실제 값은 DB가 정본이다. 기본값에서는 **삼성전자만 매수**하고 KODEX 반도체·SOXL은 꺼져 있다(분봉 수집·차트는 계속). 익절 %도 종목별이라 KODEX·SOXL에 삼성전자 값이 강제되지 않는다.
- **삼성전자는 마틴게일(2026-09-30).** 마틴게일을 켠 종목(기본값: 삼성전자)에만 적용, 그 외 종목은 보유 중이면 더 사지 않는다. **예전의 "물타기 안 한다" 원칙은 폐기.** 사이클 상태(몇 단계인지, 직전 매수가)는 따로 저장하지 않고 매매 기록에서 계산한다. 오늘의 목표는 수익률보다 **최대한 많이 거래해 보는 것**이라 기준을 좁게 잡았다(전부 임시값, 결과 보고 바꾼다).
  - **시작:** 첫 1주. 시점은 기존 분봉 저점 근접+반등 신호(임시). 이미 1주를 들고 있으면 그게 1단계라 새로 사지 않는다.
  - **최대 단계 기본값 10, 하락 간격 0.5% 고정 (2026-09-30):** 새로 만드는 종목 행의 기본값이다(코스닥150레버리지용). 이미 있는 행(삼성전자 등)은 DB 값 그대로다. 마지막 단계 손절(-3%)은 10단계 기준으로 걸린다.
  - **증권사 앱에서 직접 거래한 물량:** KIS 잔고를 조회할 때(지금은 계좌 화면을 열 때) 그 값과 봇 매매 기록을 비교해 차이를 가상 매매(SYNC)로 DB에 남긴다. 직접 매수분은 하나의 매수 단계로 취급된다. 앱에서 직접 판 물량은 매도가를 현재가로 추정하고, 봇이 방금 낸 주문(10분 이내)이 있으면 미체결일 수 있어 매도 반영을 건너뛴다.
  - **추가 매수:** **평단** 대비 **-0.5%**(호가 단위 반올림)에 닿을 때마다 보유 수량이 2배가 되도록(= 지금 보유수만큼 더) — 1,2,4,8,16주, **최대 5단계**, 6단계부터는 사지 않는다. 기준은 직전 매수가가 아니라 평단이다(2026-09-30 변경 — 평단 기준이라 2배씩 사면 간격이 좁아져 10단계 끝이 첫 매수가 대비 약 -2.6%다). 배분 한도 때문에 2배를 살 수 없으면(리스크 가드 거부) 사지 않는다.
  - **익절:** 평단 +0.5%에서 전량 매도.
  - **5단계 손절:** 5단계까지 산 뒤 현재가가 **평단**의 **-3%** 이하이면 전량 매도. 1~4단계에는 손절이 없다.
  - **매도 후 재진입 (신호 불필요):** 익절 뒤엔 매도가 **-0.5%**, 손절 뒤엔 매도가 **-1%**(호가 단위 반올림) 이하로 내려오면 첫 1주부터 다시 시작한다. 재진입 규칙이 걸려 있는 동안엔 분봉 신호를 보지 않는다. 익절/손절 구분은 "매도가 > 그 사이클 평단"이다.
  - 27만원대 기준 1→2→4→8→16주 누적은 약 843만원이라 국내 1000만원 안에 들어간다.
- **5거래일 넘게 안 들고 있는다.** (타임스톱 — **미정**. 코드에는 없고, 마틴게일과 함께 어떻게 할지 아직 정하지 않았다)

## 아직 정하는 중 (2026-09-29 밤에 열린 질문, 다음에 이어서 정함)

- **매수 판단에 AI가 꼭 필요한가?** 지금까지 나온 진입 아이디어(오늘 -5%/-10%면 매수 등)는 전부 숫자 기준이라, AI 없이 코드만으로도 할 수 있다는 얘기가 나왔다. → **결론 안 남.** 다음 대화에서 "규칙만으로 갈지" "AI를 어디에 쓸지" 다시 정한다.
- 구체적인 매수 규칙(몇 % 빠지면 사는지 등 정확한 숫자)
- 클라우드 서버 배포 (지금은 로컬에서만 테스트 중이라 컴퓨터 끄면 봇도 멈춘다)
- **진입 판단 데이터 형태 (2026-09-29):** 차트 이미지를 매번 캡처해서 보여주는 방식 대신, KIS API로 받은 OHLC(시가·고가·저가·종가)·거래량 숫자로 판단하는 쪽으로 방향을 잡음. 자동화·재현 가능성 때문. **국내 분봉 조회(`FHKST03010200`) 스펙 확인 완료, 구현 완료** — 당일 데이터만·1회 최대 30건이라 받는 족족 DB(`minute_candle`)에 쌓는 구조로 만듦.
- **분봉 기반 진입 규칙 (2026-09-29, 검증 전, 두 번째 버전):** 첫 시도는 모멘텀(5분 수익률)+거래량 급증 동시 충족이었는데, 사용자가 "거래량까지 볼 필요 있나, 횡보하다 저점 찍으면 거기서 사는 걸 원한다"고 해서 폐기. 지금은 **당일 저점(그날까지의 최저가) 대비 0.3% 이내로 붙었다가 직전 분봉보다 올랐으면(반등 시작) 매수** — 거래량 조건 없음. 분봉이 15개(약 15분) 안 쌓였으면 매수 안 함(장 시작 직후 오탐 방지). AI 판단 없이 순수 숫자 규칙, `strategy/EntryRule.kt`의 `SupportBounceEntryRule`, 설정은 `quantlog.strategy.entry.*`. **실제 EntryScheduler에 연결되어 정규장 중 자동 매수함**(모의투자). 임계값(0.3%, 15개)은 첫 가설값이라 로그가 쌓이면 검증해야 확정.
- **차트 화면에 표시하는 종목 (2026-09-29):** 삼성전자(005930)·SK하이닉스(000660)·SOXL(AMEX) 세 개, `com.quantlog.chart.WATCHED_SYMBOLS`. 단, **자동매수(EntryScheduler) 감시 종목은 그대로 삼성전자·KODEX반도체(091160)** — 화면 표시용 종목과 자동매매 대상 종목을 의도적으로 분리해뒀다(사용자가 화면 종목은 바꾸되 자동매매 대상은 그대로 두기로 함). SOXL 해외 분봉도 조회·저장된다(`HHDFS76950200`). 차트 시각은 항상 KST로 보여주고(미국 분봉은 뉴욕 현지 시각 가정 → KST 변환), DB 조회 날짜는 거래소 현지 기준이다(2026-09-30 수정, 현지 시각 가정은 서버 DB로 확인 필요).
- **풋/콜 옵션을 진입 판단에 쓸지 (2026-09-29):** 검토 대상. (정정 2026-09-29: KIS에도 국내 옵션 API가 있다 — `국내옵션전광판_콜풋`(FHPIF05030100), 주식옵션 호가/체결 등. 삼성전자 같은 개별 주식옵션의 행사가별 미결제약정이 여기서 나오는지, 모의투자에서 되는지는 실제 호출로 확인 필요.) **옵션을 사고파는 게 아니라, 미결제약정이 몰린 가격대(맥스페인 등)를 신호로만 보고 그 가격대에 현물을 매수하는 방식** — 그래서 "롱만 한다" 원칙과 안 부딪힘(사용자 확인). 데이터 소스 후보 조사 완료(무료 웹 도구/유료 API/비공식 스크래핑, 공식 무료 API는 없음) — **일단 보류, 분봉 기반 진입 판단부터 먼저 진행하기로 함.**

## 봇의 판단 습관

- 근거 없으면 안 산다. 근거는 일지에 남긴다.
- 확신 없으면 쉰다. 쉰 이유도 일지에 남긴다.
- 없는 데이터(옵션, 국채금리 등)는 아는 척하지 않는다. 아직 연결 안 됐으면 "데이터 없음"이라고 적는다.

## 절대 안 바뀌는 것

리스크 가드(시장별 자본 배분, 하루 손실 한도, 비상 정지)는 다른 모든 원칙보다 우선한다. 봇 스스로도, 학습으로도 이걸 우회할 수 없다.

## 아직 채택 안 한 아이디어 (판단에 안 씀)

- 국채금리 급등한 날은 쉰다 — 금리 데이터 연결 필요, "급등"의 기준 필요
- 콜옵션이 특정 수준이면 매수 — 옵션 데이터 연결 필요
- 익절 +2%쯤, 손절은 더 과감히 — 기록 쌓이면 비교해서 결정

## 원칙을 바꾸는 방법

1. 저와 대화해서 정하거나, 봇이 스스로 배운 걸 제안하면(`proposals/`) 제가 검토해서 반영합니다.
2. 익절·손절 같은 숫자만, 정해진 범위 안에서 자동으로 조정될 수 있습니다.
3. 거래가 적을 때(50건 미만) 나온 결과로는 원칙을 안 뒤집습니다.
4. 바꿀 때마다 이유와 날짜를 [변경 이력](principles-log.md)에 남깁니다.
