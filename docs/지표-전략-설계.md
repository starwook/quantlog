# 지표 전략 설계 (구현 계획)

2026-11-04 초안. 근거: [한투 AI 도구 조사](kis-api/한투-AI도구-조사.md), 기획서 미결 사항 10번.

## 요약

- 종목별 **네 번째 매수 옵션 "지표 전략"** 을 만든다. 지표(RSI·MACD·이동평균 등)로 조건을 정하고, **분봉**으로 계산해 신호가 뜨면 **봇이 자동으로 산다**(리스크 가드 경유). 매도는 익절·손절에 더해, 종목별로 켜면 지표 매도 신호로도 판다.
- 화면은 한투 전략빌더의 "전략 실행" 모양을 따른다: 왼쪽 전략·파라미터 / 가운데 시그널 결과·실행 로그 / 오른쪽 계좌 요약. 종목 탭(차트·백테스트·마틴게일) 옆에 "지표 전략" 탭으로 붙는다.
- **백테스트를 먼저 만든다.** 같은 지표 전략을 쌓인 분봉으로 돌려 수익률·MDD·승률을 본다. 라이브와 백테스트가 같은 판정 코드를 쓴다.
- 지표 계산은 ta4j(Java 지표 라이브러리, MIT)를 `app` 에 넣어 쓴다. 한투 코드는 라이선스가 없어 옮기지 않는다. **게이트웨이는 손대지 않는다**(분봉은 이미 쌓이고 있다).
- 3개 PR로 나눈다: ① 지표 엔진 + 프리셋 + 백테스트(주문 없음) → ② 자동 매수 옵션 + 전략 실행 화면 → ③ 지표를 자유롭게 조합하는 빌더.

## 구조 (`app` 모듈만)

새 도메인 패키지 `indicator` (패키지는 도메인 기준). **PR ① 에서 만든 것**:

| 파일 | 하는 일 |
|---|---|
| `indicator/IndicatorContext.kt` | 분봉 목록 → ta4j 시리즈. 이동평균·RSI·MACD·볼린저 등 지표 값을 i 번째 봉 기준으로 꺼낸다(같은 지표는 한 번만 만든다). i 이전 봉만 본다 |
| `indicator/IndicatorPreset.kt` | 프리셋 13개(enum). 파라미터(기본값·범위 — 화면 입력칸 범위도 여기서), 필요한 봉 수, 봉마다 매수·매도 조건 상태와 근거 문장 |
| `indicator/IndicatorEvaluator.kt` | 분봉 전체를 판정한 결과(`IndicatorTimeline`). `actionAt(i)` 는 조건이 직전 봉 거짓 → 이번 봉 참일 때만 BUY/SELL. 직전 봉 상태가 없으면(봉 부족) 신호 없음. 라이브·백테스트·화면 미리보기가 모두 이것을 쓴다 |

ta4j 는 0.17 을 쓴다 — 0.18 부터 Java 21 이 필요하고 우리는 Java 17 이다.

**나중 PR 에서 만들 것**:
- PR ②: 종목에 전략 연결 — `symbol_strategy` 에 `indicator_entry`(매수 켜기), `indicator_exit`(지표 매도 켜기), `indicator_preset`, `indicator_params`(JSON), `indicator_entry_quantity`(기본 1). 실행 로그 `indicator_signal_log`(시각, 종목, 전략, 신호, 근거, 주문번호 또는 거절 사유 — 신호가 바뀌었을 때와 주문했을 때만).
- PR ③: 직접 만든 전략 — `indicator_strategy` 테이블(이름, 조건 JSON: 지표 A, 연산자, 지표 B 또는 숫자, AND/OR), 지표 목록 `IndicatorCatalog`(ta4j 지표를 넓혀 등록). 프리셋도 같은 판정기(`IndicatorEvaluator`)로 돈다.

### 프리셋 (1단계, 13개 — 2026-11-04 사용자: 한투 10개 + 3개, 분봉에서 뜻이 바뀌는 건 이름을 바꾼다)

한투 10개는 전략빌더(`strategy_builder/strategy_core/preset/`)·백테스터(`backtester/kis_backtest/strategies/preset/`)에 같은 것이 있고 원래 일봉("N일") 기준이다. 분봉으로 옮길 때 "N일"은 "N봉"이 된다. 코드는 옮기지 않고 조건만 우리 형식으로 다시 쓴다.

|---|---|---|---|

## PR 나누기

### PR ① 지표 엔진 + 백테스트 (주문 없음, 안전) — 2026-11-04 구현
- `app/build.gradle.kts` 에 `org.ta4j:ta4j-core:0.17`.
- 위 `indicator` 패키지 3개 파일 + 프리셋 13개.
- 백테스트 `backtest/IndicatorBacktestService.kt`: 그날 분봉에 직전 거래일 분봉을 앞에 붙여 판정하고 매매는 그날 봉에서만. 보유가 없을 때 매수 신호 봉의 종가에 사고, 다음 봉부터 손절(저가) → 익절(고가) → 지표 매도(종가, 옵션) 순으로 불리하게 본다. 갭이면 시가 체결. 그날 못 판 건 마지막 종가 "미청산". 여러 날 합계: 수익률 단순 합, 최대 낙폭(누적 합의 고점 대비 %p), 승률, 수익일. 기존 `BacktestService`(저점 판단 진입)는 그대로 두었다 — 그쪽은 종가로만 청산을 보고, 합치면 기존 결과가 바뀌기 때문이다.
- 화면 `/backtest/indicator/{market}/{symbol}` (`backtest/IndicatorBacktestController.kt`, `templates/backtest-indicator.html`), 종목 탭 "지표 전략". 전략 고르기 → 파라미터·익절·손절(기본값은 종목 설정)·매도 신호 옵션 → 최근 20일 합계, 그날 거래(사고판 근거 포함), 날짜별 수익률. 저장되지 않는다.

### PR ② 자동 매수 옵션 + 전략 실행 화면
- `trading/EntryScheduler.kt` 에 네 번째 분기 `checkIndicatorEntry` — 저점 판단 진입(`checkTarget`)과 같은 모양: 보유 0주 확인 → 판정 → 직전 판정이 거짓이었을 때만 `buy()`(리스크 가드·거래 정지·`CallPriority.urgent` 그대로). 주문 방식은 다른 매수처럼 한 호가 위 지정가 + 10초 미체결 취소. 직전 판정 값은 메모리에 두고, 재기동 직후 첫 판정은 "직전 거짓"으로 보지 않는다(뜨자마자 이미 참인 신호로 사지 않게).
- 지표 매도: `trading/ExitService.kt` 의 청산 판정에 세 번째 사유 "지표 매도"를 추가 — `indicator_exit` 켠 종목만, 매도 조건이 거짓→참이 된 순간 전량. 주문은 익절·손절과 같은 길(한 호가 아래 지정가, 거래 정지·주문 대기에 막히지 않음)이라 새 매도 경로를 따로 만들지 않는다. 손절이 먼저 닿으면 손절이 이긴다.
- 실행 로그 테이블·서비스.
- 화면 `/strategy/{market}/{symbol}` (`templates/strategy.html`, 종목 탭 "지표 전략"):
  - 왼쪽: 전략 선택, 파라미터 슬라이더, 수량, 켜기/끄기 저장(`symbol_strategy` 에 저장).
  - 가운데 위: **시그널 결과** — "지금 평가" 버튼은 주문 없이 현재 분봉으로 판정만 보여 준다.
  - 가운데 아래: **실행 로그**(최근 신호·주문·거절).
  - 오른쪽: **계좌 요약** — 주문 화면이 쓰는 `/ws/portfolio` 스트림 그대로(예수금·총 평가·보유·손익).
- 설정 화면(`settings.html`)의 매수 옵션 목록에도 "지표 전략" 표시.
