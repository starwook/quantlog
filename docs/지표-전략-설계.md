# 지표 전략 설계 (구현 계획)

2026-11-04 초안. 근거: [한투 AI 도구 조사](kis-api/한투-AI도구-조사.md), 기획서 미결 사항 10번.

## 요약

- 종목별 **네 번째 매수 옵션 "지표 전략"** 을 만든다. 지표(RSI·MACD·이동평균 등)로 조건을 정하고, **분봉**으로 계산해 신호가 뜨면 **봇이 자동으로 산다**(리스크 가드 경유). 매도는 익절·손절에 더해, 종목별로 켜면 지표 매도 신호로도 판다.
- 화면은 한투 전략빌더의 "전략 실행" 모양을 따른다: 왼쪽 전략·파라미터 / 가운데 시그널 결과·실행 로그 / 오른쪽 계좌 요약. 종목 탭(차트·백테스트·마틴게일) 옆에 "지표 전략" 탭으로 붙는다.
- **백테스트를 먼저 만든다.** 같은 지표 전략을 쌓인 분봉으로 돌려 수익률·MDD·승률을 본다. 라이브와 백테스트가 같은 판정 코드를 쓴다.
- 지표 계산은 ta4j(Java 지표 라이브러리, MIT)를 `app` 에 넣어 쓴다. 한투 코드는 라이선스가 없어 옮기지 않는다. **게이트웨이는 손대지 않는다**(분봉은 이미 쌓이고 있다).
- 3개 PR로 나눈다: ① 지표 엔진 + 프리셋 + 백테스트(주문 없음) → ② 자동 매수 옵션 + 전략 실행 화면 → ③ 지표를 자유롭게 조합하는 빌더.

## 정해진 것 (2026-11-04 사용자)

| 항목 | 결정 |
|---|---|
| 주문 | 시그널이 뜨면 봇이 자동 주문. 종목별 매수 옵션으로 켠다 |
| 봉 | 분봉(`kis_minute_chart` 에 쌓인 것) |
| 백테스트 | 반드시 가져간다 |
| 반복 매수 | 진입 조건이 거짓→참으로 바뀐 순간에만 산다(쿨다운 시계 없음) |
| 보유 중 | 보유 0주일 때만 산다 |
| 봉 부족 | 직전 거래일 분봉을 앞에 붙여 계산한다 |
| 매도 신호 | 종목별 선택 옵션. 켜면 지표 매도 조건이 참이 될 때 전량 매도, 끄면 화면·로그에만 표시 |

## 구조 (`app` 모듈만)

새 도메인 패키지 `indicator` 를 만든다(패키지는 도메인 기준).

| 파일 | 하는 일 |
|---|---|
| `indicator/IndicatorCatalog.kt` | 쓸 수 있는 지표 목록(enum). 이름·파라미터(기본값·범위)·ta4j 지표 생성. 화면의 슬라이더 범위도 여기서 나온다 |
| `indicator/IndicatorStrategyDefinition.kt` | 전략 = 진입 조건 목록(지표 A, 연산자, 지표 B 또는 숫자) + AND/OR. 한투 `.kis.yaml` 과 같은 생각이지만 우리 형식(JSON)으로 저장 |
| `indicator/IndicatorEvaluator.kt` | 분봉 목록 → `BUY / HOLD / SELL` + 근거 문장(예: "MA5 172,818 > MA20 171,900 상향 돌파"). 라이브·백테스트·화면 미리보기가 모두 이것만 부른다 |
| `indicator/IndicatorStrategyEntity.kt` · `Repository` · `Service` | 전략 저장(`indicator_strategy` 테이블: 이름, 정의 JSON, 프리셋 여부) |
| `indicator/IndicatorPresets.kt` | 프리셋을 기동 시 `indicator_strategy` 에 넣는다(이미 있으면 건너뜀) |
| `indicator/IndicatorSignalLog*.kt` | 실행 로그(`indicator_signal_log`: 시각, 종목, 전략, 신호, 근거, 주문번호 또는 거절 사유). 신호가 바뀌었을 때와 주문했을 때만 남긴다(30초마다 쌓지 않게) |

`symbol_strategy` 에 칸 4개 추가(`ddl-auto: update` 라 자동 생성): `indicator_entry`(매수 켜기), `indicator_exit`(지표 매도 켜기), `indicator_strategy_id`, `indicator_entry_quantity`(기본 1). 종목마다 전략 하나. 진입·매도 조건은 같은 전략 정의 안에 둔다.

### 프리셋 (1단계, 13개 — 2026-11-04 사용자: 한투 10개 + 3개, 분봉에서 뜻이 바뀌는 건 이름을 바꾼다)

한투 10개는 전략빌더(`strategy_builder/strategy_core/preset/`)·백테스터(`backtester/kis_backtest/strategies/preset/`)에 같은 것이 있고 원래 일봉("N일") 기준이다. 분봉으로 옮길 때 "N일"은 "N봉"이 된다. 코드는 옮기지 않고 조건만 우리 형식으로 다시 쓴다.

| 프리셋 (우리 이름) | 출처 | 진입 조건 | 매도 조건 (지표 매도 옵션) |
|---|---|---|---|
| 골든크로스 | 한투 | 단기 MA 가 장기 MA 상향 돌파 (5/20) | 하향 돌파 |
| 추세 필터 | 한투 | 종가 > MA 이고 직전 봉보다 상승 (MA 60) | 종가 < MA 이고 직전 봉보다 하락 |
| 이격도 | 한투 | 종가/MA < 하단 기준 (MA 20, 99%) | 종가/MA > 상단 기준 (101%) |
| 평균회귀 | 한투 "평균회귀"(백테스터 "단기 반전") | 종가가 N봉 평균보다 M% 이상 낮음 | M% 이상 높음 |
| 연속 상승 | 한투 "연속 상승·하락" | N봉 연속 종가 상승 | N봉 연속 하락 |
| 변동성 확장 | 한투 | N봉 변동성이 최저권에서 급등 | 급락 |
| 강한 종가 | 한투 | 종가가 당일(고가−저가) 범위의 상위 N% | — |
| 돌파 실패 | 한투 | — (매도 전용) | 전고점 돌파 뒤 N봉 안에 다시 이탈 |
| **N봉 수익률 모멘텀** | 한투 "모멘텀"을 바꿈 — 원래는 여러 종목의 수익률 순위인데 우리는 종목이 적어 순위를 못 씀 | 최근 N봉 수익률 > x% | < −x% |
| **당일 신고가 돌파** | 한투 "52주 신고가"를 바꿈 — 분봉엔 52주가 없음 | 종가가 당일 최고가를 갱신 | — |
| RSI 과매도 반등 | 우리 추가 (한투 프리셋 아님, 지표 목록엔 있음) | RSI(14) 가 30 상향 돌파 | 70 하향 돌파 |
| MACD 교차 | 우리 추가 | MACD(12/26/9) 가 시그널선 상향 돌파 | 하향 돌파 |
| 볼린저 하단 반등 | 우리 추가 | 종가가 하단 밴드(20, 2σ) 위로 복귀 | 상단 밴드 도달 |

## PR 나누기

### PR ① 지표 엔진 + 백테스트 (주문 없음, 안전)
- `build.gradle.kts`(app)에 ta4j-core 추가. 버전은 Java·Kotlin 호환을 Gradle 로 확인하고 고정.
- 위 `indicator` 패키지(로그 제외) + 프리셋.
- 백테스트: `backtest/BacktestService.kt` 의 재생 루프를 "진입 판정 함수"를 받게 넓혀서, 저점 판단 진입과 지표 전략이 같은 루프를 쓴다(미래 봉을 안 보는 원칙·익절/손절 청산 그대로). 성과 숫자 추가: 총 수익률, 최대 낙폭(MDD), 승률, 거래 수, 여러 날 합계.
- 화면: `backtest/IndicatorBacktestController.kt` + `templates/backtest-indicator.html`, 종목 탭(`fragments/nav.html` `symbolTabs`)에 "지표 백테스트" 추가. 프리셋 고르기·파라미터 바꾸기 → 날짜별 거래·성과.

### PR ② 자동 매수 옵션 + 전략 실행 화면
- `trading/EntryScheduler.kt` 에 네 번째 분기 `checkIndicatorEntry` — 저점 판단 진입(`checkTarget`)과 같은 모양: 보유 0주 확인 → 판정 → 직전 판정이 거짓이었을 때만 `buy()`(리스크 가드·거래 정지·`CallPriority.urgent` 그대로). 주문 방식은 다른 매수처럼 한 호가 위 지정가 + 10초 미체결 취소. 직전 판정 값은 메모리에 두고, 재기동 직후 첫 판정은 "직전 거짓"으로 보지 않는다(뜨자마자 이미 참인 신호로 사지 않게).
- 지표 매도: `trading/ExitService.kt` 의 청산 판정에 세 번째 사유 "지표 매도"를 추가 — `indicator_exit` 켠 종목만, 매도 조건이 거짓→참이 된 순간 전량. 주문은 익절·손절과 같은 길(한 호가 아래 지정가, 거래 정지·주문 대기에 막히지 않음)이라 새 매도 경로를 따로 만들지 않는다. 손절이 먼저 닿으면 손절이 이긴다.
- 실행 로그 테이블·서비스.
- 화면 `/strategy/{market}/{symbol}` (`templates/strategy.html`, 종목 탭 "지표 전략"):
  - 왼쪽: 전략 선택, 파라미터 슬라이더, 수량, 켜기/끄기 저장(`symbol_strategy` 에 저장).
  - 가운데 위: **시그널 결과** — "지금 평가" 버튼은 주문 없이 현재 분봉으로 판정만 보여 준다.
  - 가운데 아래: **실행 로그**(최근 신호·주문·거절).
  - 오른쪽: **계좌 요약** — 주문 화면이 쓰는 `/ws/portfolio` 스트림 그대로(예수금·총 평가·보유·손익).
- 설정 화면(`settings.html`)의 매수 옵션 목록에도 "지표 전략" 표시.

### PR ③ 자유 조합 빌더

## 검증
- `./gradlew ktlintFormat build`.
- 단위 테스트: 지표 값(손으로 계산한 짧은 시계열과 비교), 연산자(상향 돌파는 직전 봉 대비), 프리셋 판정, 백테스트가 미래 봉을 안 보는지, 지표 매수가 리스크 가드·거래 정지를 거치는지(`EntryScheduler` 기존 테스트 방식), 같은 신호로 두 번 안 사는지, 보유 중엔 안 사는지, 재기동 직후 참인 신호로 안 사는지, 지표 매도가 손절보다 먼저 나가지 않는지·거래 정지에 막히지 않는지.
- 앱은 띄우지 않는다. 화면 확인이 필요하면 사용자에게 요청.
