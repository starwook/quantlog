# 지표 전략 설계 (구현 계획)

2026-11-04 초안. 근거: [한투 AI 도구 조사](kis-api/한투-AI도구-조사.md), 기획서 미결 사항 10번.

## 요약

- 종목별 **네 번째 매수 옵션 "지표 전략"** 을 만든다. 지표(RSI·MACD·이동평균 등)로 조건을 정하고, **분봉**으로 계산해 신호가 뜨면 **봇이 자동으로 산다**(리스크 가드 경유). 매도는 지금처럼 익절·손절이 맡는다.
- 화면은 한투 전략빌더의 "전략 실행" 모양을 따른다: 왼쪽 전략·파라미터 / 가운데 시그널 결과·실행 로그 / 오른쪽 계좌 요약. 종목 탭(차트·백테스트·마틴게일) 옆에 "지표 전략" 탭으로 붙는다.
- **백테스트를 먼저 만든다.** 같은 지표 전략을 쌓인 분봉으로 돌려 수익률·MDD·승률을 본다. 라이브와 백테스트가 같은 판정 코드를 쓴다.
- 지표 계산은 ta4j(Java 지표 라이브러리, MIT)를 `app` 에 넣어 쓴다. 한투 코드는 라이선스가 없어 옮기지 않는다. **게이트웨이는 손대지 않는다**(분봉은 이미 쌓이고 있다).
- 3개 PR로 나눈다: ① 지표 엔진 + 프리셋 + 백테스트(주문 없음) → ② 자동 매수 옵션 + 전략 실행 화면 → ③ 지표를 자유롭게 조합하는 빌더.

## 정해진 것 (2026-11-04 사용자)

| 항목 | 결정 |
|---|---|
| 주문 | 시그널이 뜨면 봇이 자동 주문. 종목별 매수 옵션으로 켠다 |
| 봉 | 분봉(`kis_minute_chart` 에 쌓인 것) |
| 백테스트 | 반드시 가져간다 |

## 정할 것 (구현 전에 묻는다)

1. **매도 시그널**: 지표 전략의 매도 조건(예: 데드크로스)으로도 팔까? 제안 — 1단계에서는 화면·로그에만 보이고 팔지 않는다(원칙집 "청산은 기계적으로, 익절·손절"). 팔게 하려면 원칙 변경이다.
2. **같은 신호 반복 매수 방지**: 조건이 계속 참이면 30초마다 또 산다. 제안 — "조건이 거짓→참으로 바뀐 순간"에만 산다(사건 기준, 시계 아님). 저점 판단 진입처럼 10분 쿨다운을 쓰는 대신이다.
3. **첫 프리셋 범위**: 제안은 아래 "프리셋" 표의 6개.
4. **전날 분봉 포함 여부**: MA60처럼 긴 지표는 장 시작 직후 봉이 모자란다. 제안 — 직전 거래일 분봉을 앞에 붙여 계산한다(밤사이 갭은 그대로 둔다). 싫으면 "봉이 모자라면 안 산다"로 간다.

## 구조 (`app` 모듈만)

새 도메인 패키지 `indicator` 를 만든다(패키지는 도메인 기준).

| 파일 | 하는 일 |
|---|---|
| `indicator/IndicatorCatalog.kt` | 쓸 수 있는 지표 목록(enum). 이름·파라미터(기본값·범위)·ta4j 지표 생성. 화면의 슬라이더 범위도 여기서 나온다 |
| `indicator/IndicatorStrategyDefinition.kt` | 전략 = 진입 조건 목록(지표 A, 연산자, 지표 B 또는 숫자) + AND/OR. 한투 `.kis.yaml` 과 같은 생각이지만 우리 형식(JSON)으로 저장 |
| `indicator/IndicatorEvaluator.kt` | 분봉 목록 → `BUY / HOLD / SELL` + 근거 문장(예: "MA5 172,818 > MA20 171,900 상향 돌파"). 라이브·백테스트·화면 미리보기가 모두 이것만 부른다 |
| `indicator/IndicatorStrategyEntity.kt` · `Repository` · `Service` | 전략 저장(`indicator_strategy` 테이블: 이름, 정의 JSON, 프리셋 여부) |
| `indicator/IndicatorPresets.kt` | 프리셋을 기동 시 `indicator_strategy` 에 넣는다(이미 있으면 건너뜀) |
| `indicator/IndicatorSignalLog*.kt` | 실행 로그(`indicator_signal_log`: 시각, 종목, 전략, 신호, 근거, 주문번호 또는 거절 사유). 신호가 바뀌었을 때와 주문했을 때만 남긴다(30초마다 쌓지 않게) |

`symbol_strategy` 에 칸 3개 추가(`ddl-auto: update` 라 자동 생성): `indicator_entry`(켜기), `indicator_strategy_id`, `indicator_entry_quantity`(기본 1). 종목마다 전략 하나.

### 프리셋 (1단계, 분봉용으로 다시 정의)

| 프리셋 | 진입 조건 | 기본 파라미터 |
|---|---|---|
| 골든크로스 | 단기 MA 가 장기 MA 를 상향 돌파 | 5 / 20 |
| 추세 필터 | 종가 > MA 이고 직전 봉보다 상승 | MA 60 |
| 이격도 | 종가 / MA < 기준 (눌림) | MA 20, 99% |
| RSI 과매도 반등 | RSI 가 기준 아래에서 위로 돌파 | 14, 30 |
| MACD 교차 | MACD 가 시그널선 상향 돌파 | 12 / 26 / 9 |
| 볼린저 하단 반등 | 종가가 하단 밴드 아래에서 위로 복귀 | 20, 2σ |

한투의 52주 신고가·연속 상승(일) 같은 일봉 전용 프리셋은 분봉에서 의미가 달라 뺀다.

## PR 나누기

### PR ① 지표 엔진 + 백테스트 (주문 없음, 안전)
- `build.gradle.kts`(app)에 ta4j-core 추가. 버전은 Java·Kotlin 호환을 Gradle 로 확인하고 고정.
- 위 `indicator` 패키지(로그 제외) + 프리셋.
- 백테스트: `backtest/BacktestService.kt` 의 재생 루프를 "진입 판정 함수"를 받게 넓혀서, 저점 판단 진입과 지표 전략이 같은 루프를 쓴다(미래 봉을 안 보는 원칙·익절/손절 청산 그대로). 성과 숫자 추가: 총 수익률, 최대 낙폭(MDD), 승률, 거래 수, 여러 날 합계.
- 화면: `backtest/IndicatorBacktestController.kt` + `templates/backtest-indicator.html`, 종목 탭(`fragments/nav.html` `symbolTabs`)에 "지표 백테스트" 추가. 프리셋 고르기·파라미터 바꾸기 → 날짜별 거래·성과.

### PR ② 자동 매수 옵션 + 전략 실행 화면
- `trading/EntryScheduler.kt` 에 네 번째 분기 `checkIndicatorEntry` — 저점 판단 진입(`checkTarget`)과 같은 모양: 판정 → `buy()`(리스크 가드·거래 정지·`CallPriority.urgent` 그대로). 주문 방식은 다른 매수처럼 한 호가 위 지정가 + 10초 미체결 취소.
- 실행 로그 테이블·서비스.
- 화면 `/strategy/{market}/{symbol}` (`templates/strategy.html`, 종목 탭 "지표 전략"):
  - 왼쪽: 전략 선택, 파라미터 슬라이더, 수량, 켜기/끄기 저장(`symbol_strategy` 에 저장).
  - 가운데 위: **시그널 결과** — "지금 평가" 버튼은 주문 없이 현재 분봉으로 판정만 보여 준다.
  - 가운데 아래: **실행 로그**(최근 신호·주문·거절).
  - 오른쪽: **계좌 요약** — 주문 화면이 쓰는 `/ws/portfolio` 스트림 그대로(예수금·총 평가·보유·손익).
- 설정 화면(`settings.html`)의 매수 옵션 목록에도 "지표 전략" 표시.

### PR ③ 자유 조합 빌더
- 프리셋 말고 직접 조건을 만든다: 지표 추가 → 연산자(상향 돌파·하향 돌파·초과·미만 등) → 비교 대상 → AND/OR.
- `IndicatorCatalog` 에 ta4j 지표를 넓혀 등록(한투 전략빌더의 지표 대부분 — 이동평균류·오실레이터·추세·변동성·거래량).
- 만든 전략을 이름 붙여 저장하고, 백테스트 탭에서 바로 돌린다.
