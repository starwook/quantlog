# 한투 AI 도구 4종 조사 — 우리 서비스를 대체할 수 있나

2026-11-04 Claude 직접 조사. 출처: 공식 저장소 `koreainvestment/open-trading-api` main (최신 커밋 3a9be59, 2026-10-28)의 `MCP/`, `strategy_builder/`, `backtester/` README와 코드. 포털(apiportal.koreainvestment.com/tools-mcp)은 JS 렌더링이라 본문을 못 읽어 저장소로 확인했다.

## 결론

- **바로 대체할 수 있는 건 없다.** 게이트웨이(한투 통로·체결통보)도, 전략(마틴게일·주기 재매수·저점 판단 진입)·청산도 대신할 도구가 없다.
- **써볼 만한 것**: 코딩도우미 MCP(키 없이 API 사양 검색 — 이 폴더의 보조), 백테스터(기획서의 "2단계 백테스트" 후보 — 마틴게일은 직접 알고리즘 작성 필요, 기획서 미결 사항 10번).
- **트레이딩 MCP는 쓰지 않는다**: "한투 키는 서버 게이트웨이에만" 원칙과 부딪힌다.

### 트레이딩 MCP가 게이트웨이를 못 대신하는 이유
- **웹소켓이 없다** → 체결통보·실시간 시세를 못 받는다. 우리 정합성(`order_fill`, 거래 정지, 체결조회 보정)의 기반이 없다.
- 호출마다 GitHub에서 샘플 Python 코드를 내려받아 실행(타임아웃 15초). 호출 제한 관리·우선순위(`CallPriority.urgent`)·멱등 주문·원문 기록이 없다.
- 리스크 가드를 안 거친다 → "모든 주문은 리스크 가드" 규칙 위반.
- **같은 앱키로 자기 토큰을 따로 받는다.** 토큰 발급 1분 1회 제한(`docs/kis-api/README.md:67`)에 걸려 서버 게이트웨이와 충돌할 수 있고, "한투 키를 로컬에 두지 않는다"(2026-10-13 사고, `docs/서버-분리.md:20`) 원칙과 맞지 않는다. 쓰려면 **별도 앱키(모의 전용)** 로만, 그리고 조회만.

### 전략빌더가 우리 전략을 못 담는 이유
- 일봉 지표 기반 시그널이다. 우리는 **실시간 틱/1초 폴링 + 분봉** 기반 단타.
- 전략 형식(`.kis.yaml`)은 "지표 조건 → 진입/청산 + 손절/익절/트레일링 %"뿐. **평단 −0.5%마다 수량 2배(마틴게일), n분마다 0주면 재매수, 체류시간 지지선 반등** 같은 포지션 늘리기·상태 기반 규칙을 표현할 수 없다 (마틴게일·물타기 코드 검색 결과 없음).
- 자동 루프가 없다(시그널 확인 후 수동 주문). 체결 대조·주문가능금액 관리도 없다.
- 지표 라이브러리는 Python이라 Kotlin `app` 에 그대로 못 가져온다.

### 백테스터를 쓰려면 알아야 할 것
- 기본이 일봉. 분봉은 한투 API로 **하루 단위, 최근 1년 이내만** (`kis_backtest/providers/kis/data.py:157`). 우리는 이미 `kis_minute_chart` 에 분봉을 쌓고 있으니 그걸 데이터로 넣는 편이 낫다.
- YAML DSL로는 마틴게일이 안 되니 **Lean Python 알고리즘을 직접 작성**해야 한다.
- Docker + Python + Node 필요, 로컬 실행. 백테스트 자체는 한투 키가 필요 없게 구성 가능(분봉을 우리 DB에서 넣으면).
