# 체결 원장 설계 (초안, 2026-10-08)

> 상태: **초안 — 사용자 확정 전.** 구현 전에 이 문서로 합의한다.

## 왜 바꾸나 (2026-10-08 실측 사고)

| 증상 | 원인 |
|---|---|
| 익절인데 화면 실현손익이 -3,400원(-0.43%). 실제는 +2,500원(+0.32%) | 실현손익을 **주문 기록 전체를 FIFO로 다시 계산**한다. 이전 날짜까지 남은 짝 없는 매수 기록과 먼저 짝지어져 평단이 틀어진다 |
| 부분체결 중인 주문이 화면에 "체결 @가격"으로 한 번에 표시 | 주문 기록(`trade`)이 주문 단위라 체결이 쪼개져 오는 걸 표현 못 한다 (44주 매수 중 3주만 체결됐는데 기록은 44주 전량 체결) |
| 마틴게일 44주 매수가 부분체결 뒤 남은 41주가 매도 이후에 체결돼 "전량 매도했는데 37주 남음" | 남은 주문의 취소가 2분간 계속 실패(원인 미확인). 보유 수량 자체는 체결통보대로 정확했다 |

## 방향

1. **기록 단위를 주문이 아니라 체결로 한다.** 체결통보 1건 = 원장 1줄(`fill`): 주문번호·종목·방향·체결수량·체결가·체결 시각.
2. **손익은 체결 시점에 확정해 저장한다.** 매도 체결 줄에 "그 시점 평단"(보유 사본 평단)과 실현손익을 같이 박는다. 주문 기록에서 다시 계산하지 않는다.
3. **KIS 잔고는 정답이 아니라 대조용이다.** 수량·평단은 체결통보로 계산하고, KIS 잔고와 어긋나면 화면에 표시한다. (지금은 KIS 잔고가 사본을 덮어쓰는 방식 — 이건 유지하되 어긋난 사실을 남긴다.)

## 통보가 빠졌을 때 (서버 재시작·WebSocket 끊김)

체결통보는 끊겨 있던 동안의 것을 재전송하지 않는다. 그래서:

- 서버 시작 직후와 WebSocket 재연결 직후, **주식일별주문체결조회**(`inquire-daily-ccld`, 모의 `VTTC0081R`)로 오늘 체결을 받아 원장에 없는 만큼만 채운다.
- 이 API는 **주문 한 건당 누적 합계**(`tot_ccld_qty`, `avg_prvs`)를 준다(쪼개진 체결 한 건씩이 아님). 그래서 보충 줄은 "주문번호 X의 체결 누적이 통보 합계보다 N주 많다 → 차이 N주를 평균가 `avg_prvs` 기준으로 1줄 추가(`source=REST_BACKFILL`)"로 만든다. 체결 시각은 알 수 없어 조회 시각을 쓰고 표시한다.
- 하루 마감(장 종료 후)에 KIS 잔고와 원장 계산 수량·평단을 대조해 어긋남을 화면에 표시한다.

## 체결통보 처리 규칙

- **체결수량·체결가만 믿는다.** 주문수량은 중복 방지 보조값. 통보가 주문수량 0으로 오는 경우가 실측됨(2026-10-07) — 0이면 주문 기록의 수량을 쓰고, 없으면 상한 없이 체결수량을 믿는다(현재 `HoldingSyncService` 동작 유지). 0으로 온 횟수는 로그에 남긴다.
- 같은 통보 중복 도착은 주문번호별 반영 누적으로 막는다(현재 동작 유지).

## 단계

1. **(먼저) 직접 원인 수정:** 취소 실패 원인 규명·로그 보강, 취소 실패가 이어지면 포기 전에 KIS 미체결 조회로 실제 상태 확인, 화면에서 부분체결을 "일부 체결"로 표시.
2. 원장 테이블(`fill`)과 체결통보 → 원장 기록. 손익 확정 저장.
3. 재시작·재연결 보충, 하루 마감 대조.
4. 화면 실현손익을 원장 기준으로 교체하고 FIFO 계산 제거. 옛 `trade` 기반 손익은 과거 기록 표시용으로만 남긴다.

## 미정·확인 필요

- 해외 체결통보 사양은 실측 전이라 1차는 국내만 적용.
- 과거(오늘 이전) 기록은 원장이 없다 — 이전 손익은 FIFO 값(부정확할 수 있음)으로 남길지, 표시를 숨길지.
- 익절 매도를 "한 호가 아래"로 내는 것 때문에 호가가 큰 종목(삼성전자 500원 ≈ 0.19%)에서 익절 수익이 거의 사라지는 문제는 **원칙 결정 사항**이라 이 설계와 별도로 정한다.
