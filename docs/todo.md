2. **취소·정정·거부 통보** — 값(`RCTF_CLS`·`RFUS_YN` 등)을 취소 주문으로 확인.

**3단계 완료 (2026-10-07):** 국내 체결 통보가 오면 `HoldingSyncService.applyFill` 이 `AccountHolding` 수량·평단을 즉시 계산해 반영한다(주문번호별 반영 수량을 기억해 중복·주문수량 초과를 막고, KIS 잔고 REST 는 정답으로 덮어쓰는 보정용). 실거래로 확인할 것: 체결 직후 `[체결통보 반영]` 로그와 이어지는 `[잔고 동기화]` 변경 내용(수량·평단 차이)이 일치하는지.

## 증권사 API 실패 기록 — 호출 맥락 (2026-10-02, 위 "서버 오류 기록"이 로그 수준은 해결)
API 호출이 실패하면 지금은 로그 한 줄(`log.warn`)로만 남아서, 나중에 "그때 왜 안 샀지?"를 알 수 없다(재시작하면 사라진다). 실패를 DB에 기록해 화면·분석에서 볼 수 있게 한다.
기록할 것:
- 언제 — 실패 시각
- 무엇을 하려던 중이었나 — 호출 종류(시세·잔고·분봉·주문·체결가 조회 등), 종목, 요청 내용(주문이면 매수/매도·수량·지정가), 호출한 쪽(진입 스케줄러·청산 스케줄러·잔고 동기화·수동 주문)
- 왜 — KIS 응답 코드(`rt_cd`/`msg_cd`)·메시지 원문, HTTP 상태, 예외 종류(타임아웃·연결 실패 포함)
- 어떻게 처리됐나 — 재시도했는지, 쿨다운에 들어갔는지, 건너뛰었는지
구현 방향: `BrokerClient` 구현체(KIS) 한 곳에서 실패를 잡아 `api_failure` 테이블에 쌓는다(호출부마다 따로 남기지 않는다). 앱키·토큰·계좌번호는 요청 내용에 남기지 않는다. 같은 오류가 매초 반복되면 행이 폭증하므로 (종류+메시지) 기준으로 묶거나 횟수만 올린다. 오래된 행은 정리한다.
